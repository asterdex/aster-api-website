## 2026-10-21

### Futures V3 & Testnet — Modify Order Queue Priority

* `PUT /fapi/v3/order` and `PUT /fapi/v3/batchOrders`: after a successful modification, the order's time priority is reset and it moves to the back of the queue at the same price level. This also applies when only the quantity is adjusted and the price is unchanged.

### Futures V3 & Testnet — BBO peg on Strategy Order

* `POST /fapi/v3/placeStrategyOrder`: added `pegPriceType` sub-order field (`COUNTERPARTY_1/_3/_5/_10/_20` or `QUEUE_1/_3/_5/_10/_20`) for `LIMIT`, `STOP`, and `TAKE_PROFIT` legs. When `pegPriceType` is set, `price` must be `"0"`.
* Added warning note: a BBO entry leg's bracket check is reported in the response body (`failureCode: -4142`), not the HTTP status.
* `GET /fapi/v3/openStrategyOrder`: added note that BBO legs return `"price": "0"` with a `pegPriceType` field.
* Updated `pegPriceType` description on `POST /fapi/v3/order`: the engine resolves the price at placement for `LIMIT` orders and at trigger for `STOP`/`TAKE_PROFIT` orders (previously stated "at trigger time" for all types).
* Removed `pegOffset` parameter from `POST /fapi/v3/order` (now resolved automatically by the engine).
* Added error codes: `-5035 INVALID_PEG_PRICE` (price must be 0 for BBO peg orders) and `-5036 PEG_PRICE_NOT_SUPPORTED` (order type does not support BBO peg).
