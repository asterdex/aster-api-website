## 2026-10-27

### Futures V3 — Get Builder User Commissions

* Added `GET /fapi/v3/builder/userCommissions` (USER_DATA, weight 5): paginated builder fees earned on trades of users under the caller's builder code.
* Parameters: `userAddresses` (up to 50, comma-separated), `startTime`, `endTime`, `page` (default 1), `limit` (default 50; max 1000), `nonce`, `signer`, `signature`.
* Covers the same trades as `GET /fapi/v3/builder/userTrades`, but returns only fee fields (`tradeId`, `insertTime`, `orderId`, `symbol`, `feeAsset`, `marginAsset`, `builderFee`, `userAddress`).
* Users' privacy mode does not apply — trades of users with privacy mode enabled are also returned.
* Time window: defaults to the past 7 days; `startTime` cannot be earlier than 90 days ago.

## 2026-10-22

### Futures V3 & Testnet — Get Income History With Pagination

* Added `GET /fapi/v3/incomePage` (USER_DATA, weight 30): paginated income history with `symbol`, `incomeType`, `startTime`, `endTime`, `page` (default 1), and `limit` (default 100; max 1000) filters.
* Response: `total`, `page`, `limit`, `hasMore`, `rows[]` (same fields as `GET /fapi/v3/income`).
* No limit on the time span; `page` × `limit` ≤ 100,000. Defaults to the recent 7 days if neither `startTime` nor `endTime` is sent.
* Requires V3 authentication parameters: `nonce`, `signer`, `signature`.

## 2026-10-21

### Futures V3 & Testnet — Modify Order Queue Priority

* `PUT /fapi/v3/order` and `PUT /fapi/v3/batchOrders`: after a successful modification, the order's time priority is reset and it moves to the back of the queue at the same price level. This also applies when only the quantity is adjusted and the price is unchanged.

### Futures V3 & Testnet — BBO peg on Strategy Order

* `POST /fapi/v3/placeStrategyOrder`: added `pegPriceType` sub-order field (`COUNTERPARTY_1/_3/_5/_10/_20` or `QUEUE_1/_3/_5/_10/_20`) for `LIMIT`, `STOP`, and `TAKE_PROFIT` legs. When `pegPriceType` is set, `price` must be `"0"`.
* Added warning note: a BBO entry leg's bracket check is reported in the response body (`failureCode: -4142`), not the HTTP status.
* `GET /fapi/v3/openStrategyOrder`: added note that BBO legs return `"price": "0"` with a `pegPriceType` field.
* Updated `pegPriceType` description on `POST /fapi/v3/order`: the engine resolves the price at placement for `LIMIT` orders and at trigger for `STOP`/`TAKE_PROFIT` orders (previously stated "at trigger time" for all types).
* Removed `pegOffset` parameter from `POST /fapi/v3/order` (now resolved automatically by the engine).
* Added error codes: `-5035 INVALID_PEG_PRICE` (price must be 0 for BBO peg orders) and `-5036 PEG_PRICE_NOT_SUPPORTED` (order type does not support BBO peg).

## 2026-10-19

### Futures V3 — Get Invitee Info

* Added `GET /fapi/v3/referral/inviteeInfo` (USER_DATA, weight 1): check whether a wallet address joined through the caller's referral.
* Parameters: `address` (EVM or Solana wallet address).
* Response when `isInvitee: true`: `walletAddress`, `dateJoined`, `feePaid`, `yourRewards`, `expiredStatus`.
* Response when `isInvitee: false`: `walletAddress` only.
* Referral relationships are valid for 365 days. An expired relationship still returns `isInvitee: true` with `expiredStatus: true`.
